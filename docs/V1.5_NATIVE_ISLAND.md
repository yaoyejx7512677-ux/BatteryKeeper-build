# v1.5 原生超级岛接入说明

BatteryKeeper v1.5 移除 v1.4 的 `TYPE_APPLICATION_OVERLAY` 仿超级岛，改为 Xiaomi HyperOS 官方原生超级岛通知。

## 本地实现链路

`BatteryMonitorService -> XiaomiIslandController -> Notification + miui.focus.param -> HyperOS SystemUI`

- 充电开始：创建岛通知。
- 充电中：同一个 notification id 更新；电量/档位变化立即更新，功率或温度变化时最低 4 秒刷新一次。
- 拔电、停止充电、关闭原生岛或停止监测服务：取消岛通知。
- 不提供岛内 Action；通知/岛点击行为使用 `contentIntent`，直接打开 `MainActivity`。
- 非 HyperOS 3 不创建第二条“伪岛”通知，也不回退到悬浮窗。

## 系统能力检测

1. `Settings.System[notification_focus_protocol] >= 3`
2. 或 `persist.sys.feature.island = true`
3. `content://miui.statusbar.notification.public` / `canShowFocus` 用于显示当前应用焦点通知权限状态。

## 小米平台前置条件

代码接入不等于正式环境一定能上岛。正式发布前仍需在小米澎湃 OS 开发者平台：

1. 为正式包名/正式签名启用“小米超级岛”服务。
2. 提交“充电实时状态”场景预审与完整方案。
3. 将测试设备加入设备白名单做联调。
4. 提交正式 APK 完成上线验证。

正式测试必须使用 BatteryKeeper 的 release keystore。临时测试签名与平台登记证书指纹不一致时，不应作为正式权限验证依据。

## 当前模板

当前实现采用官方开发指南示例的 `imageTextInfoLeft + picInfo` 结构：

- `frontTitle`：充电档位，例如“快充”“超级快充”
- `title`：电量，例如 `62%`
- `content`：电池侧功率 + 温度，例如 `32.4 W · 38.1℃`
- `baseInfo`：同步用于焦点通知/展开态兜底
- `ticker` / `aodTitle`：提供 OS2/息屏相关基础信息（v1.5 主目标仍为 OS3 原生超级岛）

后续若小米场景审核指定了模板编号或字段约束，应以审核通过的模板为准调整 JSON。
