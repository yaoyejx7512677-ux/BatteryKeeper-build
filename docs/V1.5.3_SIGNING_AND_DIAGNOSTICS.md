# BatteryKeeper v1.5.3：固定签名与超级岛诊断

## 本版目标

v1.5.3 不再假设“岛消失 = App 主动取消”。它把超级岛生命周期拆成三层观测：

1. 监测服务是否仍有心跳；
2. BatteryKeeper 的通知 #1501 是否仍存在于 `NotificationManager.activeNotifications`；
3. BatteryKeeper 最近是否主动 `cancel(1501)`，以及原因。

如果摄像头区域已经没有超级岛，但设置页显示“监测心跳正常 + #1501 存在 + 最近没有主动取消”，即可基本判断为 HyperOS SystemUI 收起/权限策略，而不是 BatteryKeeper 自己把岛删掉。

如果已插电、服务心跳正常，但 #1501 被系统移除，v1.5.3 会在下一次采样自动补发一次，并累计“自动恢复”次数；它不会在 #1501 仍存在时高频刷通知。

## 固定签名

GitHub Actions 的临时 Debug keystore 每个 Runner 都可能不同。v1.5.3 改为从 GitHub Actions Secrets 恢复同一张永久 keystore，并让 Debug 构建也使用它。

需要 4 个 Secrets：

- `BATTERYKEEPER_KEYSTORE_B64`
- `BATTERYKEEPER_STORE_PASSWORD`
- `BATTERYKEEPER_KEY_ALIAS`
- `BATTERYKEEPER_KEY_PASSWORD`

私钥/密码绝对不要提交到公开仓库。`.gitignore` 已忽略 `*.jks`、`*.keystore` 和 `keystore.properties`。

## 一次性迁移注意事项

v1.5.0～v1.5.2 使用过不同的随机 Debug 证书，因此 v1.5.3 固定签名包无法覆盖安装旧包。第一次切换到固定签名需要卸载旧包再安装，会清除 Android 应用私有数据。

从 v1.5.3 开始，只要永久保管并继续使用同一张 keystore，后续 v1.5.4、1.6、2.0 都可以正常覆盖升级。
