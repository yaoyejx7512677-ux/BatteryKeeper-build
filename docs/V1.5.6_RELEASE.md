# BatteryKeeper v1.5.6

正式商店构建版本，versionCode 16。

## 发布方式

- GitHub Actions 使用 `assembleRelease` + `bundleRelease`，不再发布 debug 重签包。
- Release 明确 `debuggable=false`，启用 R8 (`minifyEnabled`) 与资源压缩 (`shrinkResources`)。
- 继续使用现有 `BATTERYKEEPER_*` 固定签名 Secrets，保证从固定签名版本正常升级。
- CI 会检查包名、版本号、debuggable 标志和 APK 签名。

## 安装包减负

v1.5.5 使用 bundled 中文 OCR 模型，体积较大。v1.5.6 改为 bundled Latin OCR：图片导入只识别日期、百分比、mAh、循环数字与 `OSx.x` 字样，再使用 OCR 坐标进行结构化关联，不再依赖中文标签识别。因此仍可离线运行、无需 Google Play Services，同时显著降低 OCR 模型体积。

另外移除未使用的 Fragment 与 lifecycle-runtime-compose 依赖，只保留 arm64-v8a，并限制依赖资源为中英文。

## 截图识别修复

旧算法按 OCR 返回的纯文本顺序，以日期字符串切段。当 OCR 把右侧 OS 版本或循环次数排到下一段时，会出现：

- 97.04% 能识别，但 6793mAh / 295 次丢失；
- 295 次错误串到 2026-05-20；
- 多条历史记录错误复用第一条 `OS4.0.0.26.XPCCNXM`。

v1.5.6 改为视觉坐标解析：日期作为每条记录的纵向锚点，只在该条记录的视觉区域内查找健康度、mAh、循环次数和 OS 版本。不会把其它行的数据作为全局回退。

## 系统版本识别

- 当前设备：从 `Build.VERSION.INCREMENTAL` / `Build.DISPLAY` 提取 `OS3/OS4` 版本。
- 图片：每条历史记录独立匹配其所在行的 OS 版本。
- Bugreport：解析 `ro.mi.os.version.incremental` 等系统属性，并写入报告来源元数据。
